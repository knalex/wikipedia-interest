# Інтерес до тем у Вікіпедії — навичка для AI-агента

Навичка у форматі [Agent Skills](https://agentskills.io/specification), з якою
агент аналізує статистику переглядів Вікіпедії, будує графіки та готує короткі
звіти. Звіти допомагають командам B2C-продуктів вирішити, які теми розвивати і
якими мовами запускатися. Повний опис завдання — у [TASK.md](TASK.md).

Проєкт робиться поетапно, і кожен етап перевіряється окремо. У цьому файлі
описано, що зроблено і як це перевірено.

## Структура

```
.
├── README.md                     # цей файл: хід роботи
├── TASK.md                       # опис завдання
└── .claude/skills/wikipedia-interest-analysis/
    ├── SKILL.md                  # інструкції для агента
    ├── scripts/resolve_topic.py  # код етапу 1 (лише стандартна бібліотека Python)
    ├── tests/                    # офлайн-тести і записані відповіді API
    ├── examples/                 # 21 запит: запит користувача, команда, вивід
    └── docs/
        ├── haiku-evaluation.md   # протокол усіх раундів перевірки на Claude Haiku 4.5
        └── haiku-runs/           # останній прогін: один діалог на кожне питання
```

Навичка лежить у `.claude/skills/`, щоб Claude Code підхоплював її
автоматично. Завдання вимагає, щоб усі матеріали й код були в директорії
навички, тому поза нею лише `README.md` і `TASK.md`.

## Етап 1: визначення теми

### Навіщо він потрібен

Pageviews API рахує перегляди окремої статті за її точною назвою. Назви
статей рідко збігаються з дослівним перекладом. Якщо назву вгадати
неправильно, API повертає порожній ряд, і це легко сплутати з «інтересу
немає». Етап 1 знімає це вгадування: з фрази користувача він дає точний
перелік статей для кожного мовного розділу.

### Як це працює

Скрипт іде через **Wikidata**, де одне поняття (QID) пов'язане зі статтями в
усіх мовних розділах. На виході — «кошик теми»: основне поняття, статті та їхні
перенаправлення по мовах, а також ширші й вужчі поняття, які можна
запропонувати користувачу.

Основні рішення:

1. **Спершу поняття, потім статті.** Агент передає слова користувача і
   англійське формулювання (`--query uk:... --query en:...`). Перемагає
   поняття, на якому сходяться кілька формулювань. Далі — точна назва краще
   за збіг за початком. Нічию розв'язує лише перевага в 3 рази за кількістю
   мовних розділів зі статтею, інакше статус `ambiguous` і питання
   користувачу.
2. **Пов'язані поняття ніколи не додаються мовчки.** Ширші поняття (для
   інтервального голодування — «піст») і вужчі (для астрономії —
   астрофізика, космологія…) лише пропонуються. Додаються вони через
   `--include` або `--scope extended`.
3. **Перенаправлення рахуються.** Pageviews зараховує перегляди
   перенаправлення його власній назві, тому в кошик потрапляють і вони.
4. **Якщо статті немає, це факт, а не нуль.** Для таких розділів скрипт шукає
   сторінки з точно такою назвою і згадки фрази в інших статтях. Знахідки
   йдуть як докази для користувача, у підрахунок вони не потрапляють.
5. **Агент не вирішує за користувача.** Якщо значення визначили формулювання
   агента, а не слова користувача («Меркурий» → «Mercury (planet)»), скрипт
   готує уточнювальне питання першим пунктом `next_steps`. Те саме, якщо
   фраза користувача — лише прізвище.
6. **Помилки розрізняються.** Неіснуючий мовний розділ (`tlh`) повертає
   `unknown_wikipedia_edition`, а не мережеву помилку. Мережева помилка
   нічого не каже про тему.
7. **Усе, що бачить агент, — українською,** відповідь користувачу теж.
   JSON-ключі, статуси та коди попереджень лишаються англійськими: це
   контракт для наступних етапів.

### Приклад

Запит із завдання: *«Порівняй зростання інтересу до інтервального голодування
в польськомовній та чеськомовній Wikipedia за останні два роки».*

```bash
cd .claude/skills/wikipedia-interest-analysis
WIKIPEDIA_RESOLVER_CONTACT="you@example.com" python3 scripts/resolve_topic.py \
  --query "uk:інтервальне голодування" --query "en:intermittent fasting" \
  --targets pl,cs \
  --user-message "Порівняй зростання інтересу до інтервального голодування в польськомовній та чеськомовній Wikipedia за останні два роки." \
  --out basket.json
```

Скорочений результат (повний — у [`examples/01_intermittent_fasting.stdout.json`](.claude/skills/wikipedia-interest-analysis/examples/01_intermittent_fasting.stdout.json)):

```json
{
  "status": "partial",
  "core": {"entity_id": "Q1666254", "label": "Інтервальне голодування", "language_editions_with_article": 31},
  "coverage": {
    "pl": {"core_title": null, "broader_with_article": [{"entity_id": "Q44602", "label": "піст", "title": "Post"}]},
    "cs": {"core_title": "Přerušovaný půst", "included_articles": 1, "included_redirects": 0}
  },
  "warnings": [{"code": "core_missing"}, {"code": "asymmetric_basket"}],
  "next_steps": [
    "Відповідай користувачу українською, навіть якщо він писав іншою мовою.",
    "Перевір, що --targets (pl, cs) — це саме ті мовні розділи, які назвав користувач, без пропусків; якщо чогось бракує, перезапусти з повним списком.",
    "Скажи користувачу: у pl.wikipedia немає статті про «Інтервальне голодування» (Q1666254).",
    "За бажанням переклади тему мовою pl і перезапусти, додавши --query pl:<фраза>.",
    "Запропонуй ширше поняття Q44602 «піст» (pl: Post) через --include Q44602; попередь, що воно ширше і це не та сама тема."
  ]
}
```

Висновок для користувача: у польській Вікіпедії немає окремої статті про
інтервальне голодування. Фраза «post przerywany» трапляється лише всередині
3 інших статей. Тому пряме порівняння неможливе. Можна рахувати лише чеську
статтю або перейти до ширшої теми «піст», але тоді треба чесно сказати, що
порівняння нерівноцінне.

Усі 21 приклад (приклади із завдання, неоднозначності, неіснуючий розділ,
вигадана тема, опечатка, переклад ширшим поняттям, подія 2026 року) з
запитами користувачів і командами — у
[`examples/README.md`](.claude/skills/wikipedia-interest-analysis/examples/README.md).

### Запуск

- Потрібен лише Python 3.10+, залежностей немає.
- Мережа потрібна для `www.wikidata.org` і `<мова>.wikipedia.org`.
- `WIKIPEDIA_RESOLVER_CONTACT` — email або URL для заголовка User-Agent, як
  вимагає політика Wikimedia. Без нього скрипт не запускається.
- Статуси, поля та правила для агента описано в
  [`SKILL.md`](.claude/skills/wikipedia-interest-analysis/SKILL.md).

## Як перевіряли

Код написано за допомогою AI-асистента (Claude Code). Його результат
перевірявся на трьох рівнях.

1. **Реальні дані замість припущень.** Перед написанням логіки ми вручну
   дослідили відповіді Wikidata і Вікіпедії для прикладів із завдання. Так
   з'ясувалося, що:
   - у польській Вікіпедії немає статті про інтервальне голодування;
   - у астрономії 69 підкласів, тож автоматично додавати пов'язані поняття
     не можна;
   - пошук «вивчення англійської мови» знаходить «International Corpus of
     English», тому потрібне друге, англійське формулювання;
   - QID, запропонований в одній із чернеток іншим AI-асистентом (Q911526),
     неправильний: справжній — Q1666254.

   Твердження AI ми звіряли з API. Наприклад, польська стаття «Głodówka
   lecznicza» виявилася іншим поняттям (лікувальне голодування, Q352490).
   Про інтервальне голодування там лише назви джерел у виносках.
2. **Офлайн-тести** (`python3 -m unittest discover -s tests`). 17 тестів
   відтворюють записані відповіді API для 10 еталонних запитів і перевіряють
   помилки аргументів і ранжування. Тести не потребують мережі і не залежать
   від змін у Wikidata. Записи оновлюються через `tests/record_fixtures.py`.
3. **Прогони на Claude Haiku 4.5.** 13 раундів, від 1 до 17 сценаріїв у
   кожному. Агент бачив лише `SKILL.md` і повідомлення користувача, його
   відповіді звірялися з файлом кошика. Кожна знайдена проблема виправлялася
   і перевірялася повторно. Подробиці — у
   [`docs/haiku-evaluation.md`](.claude/skills/wikipedia-interest-analysis/docs/haiku-evaluation.md).

## Відомі обмеження етапу 1

- **Прізвища без імені** («Шевченко»). Пошук Wikidata не повертає людей, лише
  селища й елемент «прізвище», тож агент може підставити кандидата сам.
  Пріоритет низький: для вибору теми чи мови продукту користувачі питають про
  поняття, а людину зазвичай називають повністю.
- **Схожі поняття поза структурою Wikidata** (як «Głodówka lecznicza»)
  автоматично не знаходяться.
- **Список пов'язаних понять неповний.** На одну властивість перевіряється
  не більше 50 понять (`related_truncated`).
- **Мова відповіді.** Дешева модель інколи вставляє в українську відповідь
  окремі слова іншими мовами.
