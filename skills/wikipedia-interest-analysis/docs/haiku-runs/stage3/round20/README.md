# Раунд 20: захист від вибору значення за користувача

Після збою 05 у [раунді 19](../round19/README.md) `resolve_topic.py` з `--entity`
і `--query` перевіряє, чи слова користувача самі неоднозначні. Якщо так, а
відповіді користувача (другого `--user-message`) немає, повертає
`needs_confirmation` з попередженням `entity_needs_confirmation`, і етап 2
такий кошик не приймає. Email контакту замінено на `you@example.com`.

| Сценарій | Оцінка | Що сталося |
|---|---|---|
| [05 Меркурій](05_mercury.md) | ✅ | Спитав, який Меркурій; після «планета» — `--entity Q308` з обома повідомленнями, скрипт прийняв, далі етапи 2–3 |
| [06 ШІ](06_ai_abbreviation.md) | ✅ | Попросив підтвердити «штучний інтелект»; після «так» — етапи 2–3 з рядком «за весь період» |
| [08 Шевченко](08_shevchenko.md) | ✅ | Спитав, чи йдеться про Тараса Шевченка; після «так» — етапи 2–3 |

**Разом: 3 ✅.** Захист не заважає правильному сценарію; у всіх трьох агент
спершу питав. Живі перевірки поза Haiku: `--entity` без підтвердження дає
`needs_confirmation` для «ШІ», «Меркурий», «Шевченко» і не спрацьовує для
однозначного «кава».
